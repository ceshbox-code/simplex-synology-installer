💜 Что такое SimpleX?

SimpleX — это первый мессенджер, который не требует идентификаторов пользователей: нет номеров телефонов, никнеймов или публичных ключей, привязанных к личности. Вместо этого каждый пользователь получает уникальные одноразовые адреса для каждого соединения.

🚀 Философия и преимущества

💡 Почему SimpleX уникален?
  • Нет глобальной идентификации — вы не привязаны к номеру телефона или email. Ваш профиль существует только у ваших контактов.
  • Одноразовые адреса — для каждого нового контакта создаётся уникальный адрес. Прекратили общение — адрес удаляется, связь невозможно восстановить.
  • Защита от спама — поскольку каждый адрес уникален и используется только для одного контакта, спам технически невозможен.
  • Вы контролируете сервер — запустив свой SMP, XFTP и TURN сервер, вы полностью контролируете свою инфраструктуру. Никто не видит, кто с кем общается.
  • Квантово-устойчивое шифрование — SimpleX использует двойное шифрование с пост-квантовым алгоритмом, защищая переписку даже от будущих квантовых компьютеров.
  • Открытый исходный код — весь код доступен на GitHub, что позволяет любому независимо проверить его безопасность.
📌 Важно понимать
SimpleX — это не очередной мессенджер с "режимом инкогнито". Это принципиально иная архитектура, где отсутствие идентификаторов заложено в основу. Вы общаетесь не с "пользователем", а с конкретным адресом, который существует ровно столько, сколько нужно.
✅ Итог
Запустив свой сервер SimpleX, вы получаете полностью приватное средство общения, где никто, включая вас как администратора, не может видеть переписку пользователей (она сквозная зашифрована), а метаданные (кто с кем общается) недоступны сторонним наблюдателям.

🖥️ Подробная инструкция по установке сервера

1 Подготовка NAS

1.1 Установка Docker

  1. Откройте Package Center в DSM.
  2. В поиске введите Docker (для DSM 7.2+) или Container Manager (для DSM 7.1).
  3. Нажмите Установить и дождитесь завершения.
  4. После установки откройте Docker/Container Manager хотя бы один раз для завершения инициализации.

1.2 Включение SSH

  1. Откройте Панель управления → Терминал и SNMP → Терминал.
  2. Поставьте галочку «Включить службу SSH».
  3. Порт: 22 (или измените на нестандартный для безопасности).
  4. Нажмите Применить.

1.3 Проверка свободного места

df -h /volume1

Убедитесь, что доступно минимум 5 ГБ на целевом томе.

2 Настройка DNS-записей

⚠️ Важно: DNS-записи должны быть созданы ДО запуска скрипта установки. Распространение DNS может занять от 5 минут до 24 часов.

У регистратора вашего домена создайте следующие A-записи (замените ваш_внешний_IP на реальный IP):

ПоддоменТипЗначениеНазначение
smp.ваш-домен.ruAваш_внешний_IPSMP-сервер (сообщения)
files.ваш-домен.ruAваш_внешний_IPXFTP-сервер (файлы)
turn.ваш-домен.ruAваш_внешний_IPTURN/STUN (звонки)
info.smp.ваш-домен.ruAваш_внешний_IPВеб-панель управления

Проверьте корректность записей:

dig +short smp.ваш-домен.ru
dig +short files.ваш-домен.ru
dig +short turn.ваш-домен.ru
dig +short info.smp.ваш-домен.ru

Все четыре команды должны вернуть ваш внешний IP-адрес.

3 Настройка проброса портов на роутере

Войдите в панель управления роутером и создайте правила проброса (Port Forwarding) на внутренний IP вашего NAS:

ПортПротоколНазначениеОбязателен
5223TCPSMP (резервный порт)Да
5224TCPSMP (основной порт, TLS)Да
7788TCPXFTP (передача файлов, TLS)Да
3478TCP + UDPTURN/STUN (установка соединения)Да
5349TCPTURNS (звонки через TLS)Да
49152–65535UDPTURN (медиа-трафик звонков)Для звонков
💡 Примечание: Диапазон 49152–65535 UDP необходим только для аудио- и видеозвонков. Если звонки не планируются, можно ограничиться портами 3478 и 5349.

4 Настройка Брандмауэра DSM

  1. Откройте Панель управления → Безопасность → Брандмауэр.
  2. Нажмите Изменить правила в активном профиле.
  3. Добавьте правила Разрешить для каждого порта из таблицы выше.
  4. Убедитесь, что правило стоит выше правила «Запретить всё» (если такое есть).
  5. Нажмите OK → Применить.
⚠️ Важно: После применения правил брандмауэра убедитесь, что вы не потеряли доступ к DSM. Всегда держите открытым второе окно браузера с DSM для отката изменений.

5 Запуск установки

  1. Подключитесь по SSH:
    ssh ваш_логин@IP_вашего_NAS
  2. Получите права суперпользователя:
    sudo -i
  3. Запустите скрипт установки:
    curl -fsSL https://raw.githubusercontent.com/ceshbox-code/simplex-synology-installer/main/install.sh | /bin/bash
  4. Ответьте на вопросы скрипта (первый вопрос — выбор языка):
    • Язык интерфейса — выберите 1 для русского или 2 для английского.
    • Базовая директория — выберите номер тома из предложенного списка (по умолчанию /volume1/docker/simplex).
    • Каталог веб-файлов — выберите том с папкой web для панели управления (например, /volume1/web/simplex).
    • Внешний IP — скрипт определит автоматически, подтвердите или введите вручную.
    • Доменное имя — введите ваш домен, например: ваш-домен.ru.
    • Email — для уведомлений администратора (можно нажать Enter для значения по умолчанию).
  5. Дождитесь завершения. Скрипт выполнит создание директорий, сертификатов, загрузку зафиксированных версий образов (SMP/XFTP v6.5.2, coturn 4.6.3-r0), запуск контейнеров и генерацию веб-страниц.

6 После установки

6.1 Сохранение данных подключения

Скрипт создаст файл CONNECTION_DETAILS.txt с адресами SMP, XFTP, TURN и паролями (путь зависит от выбранного тома):

cat /volume1/docker/simplex/CONNECTION_DETAILS.txt
⚠️ Никому не передавайте этот файл! Он содержит все секреты вашего сервера.

6.2 Настройка Web Station

  1. Откройте DSM → Web Station → Настройки веб-сервера.
  2. Нажмите Создать.
  3. Заполните параметры:
    • Описание: SimpleX Control Panel
    • Корневая папка: /volume1/web/simplex (том, который вы выбрали при установке на шаге 5)
    • Веб-сервер: Apache HTTP Server 2.4
    • PHP: Нет (не требуется)
  4. В разделе URL-адрес укажите: info.smp.ваш_домен.ru
  5. Нажмите OK.
📋 Итоговая конфигурация Web Station:
Корневая папка: /volume1/web/simplex
Веб-сервер: Apache HTTP Server 2.4
URL: info.smp.ваш_домен.ru

6.3 Пароль веб-панели

При установке скрипт выводит логин и пароль для доступа к qrsmp.html. Пароль показывается только один раз. Если вы его не сохранили, сбросьте:

# Генерация нового пароля
NEW_PASS=$(openssl rand -base64 16 | tr -d '/+=' | cut -c1-16)
HASH=$(openssl passwd -apr1 "$NEW_PASS")
printf 'admin:%s\n' "$HASH" > /volume1/web/simplex/.htpasswd
echo "Новый пароль: admin / $NEW_PASS"

6.4 Проверка работоспособности

  1. Откройте панель управления: https://info.smp.ваш_домен.ru/qrsmp.html
  2. Введите логин admin и сохранённый пароль.
  3. Все три сервиса (SMP, XFTP, TURN) должны отображаться как «● РАБОТАЕТ».
  4. Если статус отличается — проверьте логи:
    docker logs simplex-smp
docker logs simplex-xftp
docker logs simplex-turn

6.5 Настройка клиента SimpleX Chat

  1. Сообщения и файлы: откройте панель управления, нажмите «Показать» на адресах SMP и XFTP, скопируйте их. В приложении SimpleX Chat перейдите в Настройки → Настройки серверов → Настроить вручную и вставьте адреса.
  2. Звонки (TURN/STUN): на панели нажмите «Показать» в блоке TURN/STUN, затем «Копировать все». В приложении перейдите в Настройки → Звонки → ICE servers и вставьте скопированные строки. Если звонки не требуются — пропустите этот шаг.
  3. Первый контакт: нажмите + в списке чатов → Пригласить друга → отсканируйте QR-код собеседника или отправьте ему ссылку-приглашение.

💾 Восстановление из бэкапа

Каждый день в 03:00 создаётся архив бэкапа (simplex-backup-ГГГГММДД_ЧЧММСС.tar.gz) с конфигурацией, паролями, identity и данными SMP/XFTP. Архивы хранятся 14 дней в backups/ внутри базовой директории.

Для восстановления скачайте и запустите restore.sh на NAS (от имени root):

curl -fsSL https://raw.githubusercontent.com/ceshbox-code/simplex-synology-installer/main/restore.sh -o restore.sh
chmod +x restore.sh
sudo /bin/bash restore.sh

Скрипт работает пошагово:

  1. Выбор архива — сканирует все тома и показывает пронумерованный список найденных бэкапов с датой и размером.
  2. Проверка целостности — проверяет архив (gzip/tar), построчно выводит список файлов внутри и отдельно проверяет алгоритм ключа транспорта SMP (должен быть Ed25519) — это позволяет отловить повреждённые сертификаты ещё до восстановления.
  3. Режим восстановления — на выбор: (1) с исходными настройками (тот же том, домен, IP) или (2) с новыми настройками, где скрипт заново предложит выбрать том для данных и веб-файлов, внешний IP и домен — как в основном установщике.
  4. Запуск — распаковывает архив, при необходимости перевыпускает сертификат SMP и поднимает контейнеры, выводя итоговый отчёт с адресами подключения.
⚠️ При восстановлении с новыми настройками (режим 2)Не забудьте обновить DNS A-записи, проброс портов на роутере и правила Брандмауэра DSM под новый домен/IP, а также перенастроить корневую папку Web Station на новую веб-директорию.

🚀 Philosophy & Benefits

💡 Why is SimpleX unique?
  • No global identification — you are not tied to a phone number or email. Your profile exists only with your contacts.
  • Disposable addresses — each new contact receives a unique address. Stop communicating — the address is deleted, the connection cannot be restored.
  • Spam protection — since each address is unique and used only for one contact, spam is technically impossible.
  • You control the server — by running your own SMP, XFTP, and TURN server, you have full control over your infrastructure. No one sees who is talking to whom.
  • Quantum-resistant encryption — SimpleX uses double encryption with a post-quantum algorithm, protecting your conversations even from future quantum computers.
  • Open source — all code is available on GitHub, allowing anyone to independently verify its security.
📌 Important to understand
SimpleX is not another messenger with an "incognito mode". This is a fundamentally different architecture where the absence of identifiers is built into the core. You communicate not with a "user", but with a specific address that exists exactly as long as needed.
✅ Bottom line
By running your own SimpleX server, you get a completely private means of communication where no one, including you as the administrator, can see users' conversations (they are end-to-end encrypted), and metadata (who is talking to whom) is not available to outside observers.

🖥️ Detailed server installation guide

1 NAS preparation

1.1 Install Docker

  1. Open Package Center in DSM.
  2. Search for Docker (for DSM 7.2+) or Container Manager (for DSM 7.1).
  3. Click Install and wait for completion.
  4. After installation, open Docker/Container Manager at least once to complete initialization.

1.2 Enable SSH

  1. Open Control Panel → Terminal & SNMP → Terminal.
  2. Check “Enable SSH service”.
  3. Port: 22 (or change to a non-standard one for security).
  4. Click Apply.

1.3 Check free space

df -h /volume1

Make sure at least 5 GB is available on the target volume.

2 DNS records configuration

⚠️ Important: DNS records must be created BEFORE running the installation script. DNS propagation may take from 5 minutes to 24 hours.

Create the following A records at your domain registrar (replace your_external_IP with the real IP):

SubdomainTypeValuePurpose
smp.your-domain.comAyour_external_IPSMP server (messages)
files.your-domain.comAyour_external_IPXFTP server (files)
turn.your-domain.comAyour_external_IPTURN/STUN (calls)
info.smp.your-domain.comAyour_external_IPWeb control panel

Verify the records:

dig +short smp.your-domain.com
dig +short files.your-domain.com
dig +short turn.your-domain.com
dig +short info.smp.your-domain.com

All four commands must return your external IP address.

3 Router port forwarding

Log in to your router's admin panel and create Port Forwarding rules to the internal IP of your NAS:

PortProtocolPurposeRequired
5223TCPSMP (backup port)Yes
5224TCPSMP (main port, TLS)Yes
7788TCPXFTP (file transfer, TLS)Yes
3478TCP + UDPTURN/STUN (connection setup)Yes
5349TCPTURNS (calls over TLS)Yes
49152–65535UDPTURN (call media traffic)For calls
💡 Note: The range 49152–65535 UDP is required only for audio and video calls. If calls are not planned, ports 3478 and 5349 are sufficient.

4 DSM Firewall configuration

  1. Open Control Panel → Security → Firewall.
  2. Click Edit Rules in the active profile.
  3. Add Allow rules for each port from the table above.
  4. Make sure the rule is above the “Deny all” rule (if any).
  5. Click OK → Apply.
⚠️ Important: After applying firewall rules, make sure you have not lost access to DSM. Always keep a second browser window with DSM open to roll back changes.

5 Run installation

  1. Connect via SSH:
    ssh your_login@NAS_IP
  2. Get superuser rights:
    sudo -i
  3. Run the installation script:
    curl -fsSL https://raw.githubusercontent.com/ceshbox-code/simplex-synology-installer/main/install.sh | /bin/bash
  4. Answer the script's questions (the first question is language selection):
    • Interface language — select 1 for Russian or 2 for English.
    • Base directory — select the volume number from the list (default /volume1/docker/simplex).
    • Web files directory — select the volume with the web folder for the control panel (e.g., /volume1/web/simplex).
    • External IP — the script detects it automatically; confirm or enter manually.
    • Domain name — enter your domain, e.g.: your-domain.com.
    • Email — for admin notifications (press Enter for the default value).
  5. Wait for completion. The script will create directories, certificates, pull pinned image versions (SMP/XFTP v6.5.2, coturn 4.6.3-r0), start containers and generate web pages.

6 After installation

6.1 Save connection details

The script creates a CONNECTION_DETAILS.txt file with SMP, XFTP, TURN addresses and passwords (the path depends on the selected volume):

cat /volume1/docker/simplex/CONNECTION_DETAILS.txt
⚠️ Do not share this file with anyone! It contains all the secrets of your server.

6.2 Web Station configuration

  1. Open DSM → Web Station → Web Service Portal.
  2. Click Create.
  3. Fill in the parameters:
    • Description: SimpleX Control Panel
    • Root folder: /volume1/web/simplex (the volume you selected during installation in step 5)
    • Web server: Apache HTTP Server 2.4
    • PHP: None (not required)
  4. In the URL section specify: info.smp.your_domain.com
  5. Click OK.

Root folder: /volume1/web/simplex
Web server: Apache HTTP Server 2.4
URL: info.smp.your_domain.com

6.3 Web panel password

During installation the script prints the login and password for qrsmp.html. The password is shown only once. If you did not save it, reset it:

# Generate a new password
NEW_PASS=$(openssl rand -base64 16 | tr -d '/+=' | cut -c1-16)
HASH=$(openssl passwd -apr1 "$NEW_PASS")
printf 'admin:%s\n' "$HASH" > /volume1/web/simplex/.htpasswd
echo "New password: admin / $NEW_PASS"

6.4 Verify operation

  1. Open the control panel: https://info.smp.your_domain.com/qrsmp.html
  2. Enter login admin and the saved password.
  3. All three services (SMP, XFTP, TURN) must show “● RUNNING”.
  4. If the status differs — check the logs:
    docker logs simplex-smp
docker logs simplex-xftp
docker logs simplex-turn

6.5 SimpleX Chat client configuration

  1. Messages and files: open the control panel, click “Show” on the SMP and XFTP addresses and copy them. In the SimpleX Chat app go to Settings → Server settings → Configure manually and paste the addresses.
  2. Calls (TURN/STUN): on the panel click “Show” in the TURN/STUN block, then “Copy all”. In the app go to Settings → Calls → ICE servers and paste the copied lines. Skip this step if calls are not needed.
  3. First contact: tap + in the chat list → Invite a friend → scan your contact's QR code or send them an invitation link.

💾 Restoring from a backup

Every day at 03:00 a backup archive (simplex-backup-YYYYMMDD_HHMMSS.tar.gz) is created with the configuration, passwords, and SMP/XFTP identity and data. Archives are kept for 14 days in backups/ inside the base directory.

To restore, download and run restore.sh on the NAS (as root):

curl -fsSL https://raw.githubusercontent.com/ceshbox-code/simplex-synology-installer/main/restore.sh -o restore.sh
chmod +x restore.sh
sudo /bin/bash restore.sh

The script proceeds step by step:

  1. Archive selection — scans all volumes and shows a numbered list of found backups with date and size.
  2. Integrity check — verifies the archive (gzip/tar), lists its contents, and separately checks the SMP transport key algorithm (must be Ed25519) — catching corrupted certificates before restoring.
  3. Restore mode — choose between (1) original settings (same volume, domain, IP) or (2) new settings, where the script prompts again for the data/web volumes, external IP, and domain — just like the main installer.
  4. Startup — extracts the archive, reissues the SMP certificate if needed, and starts the containers, printing a final report with connection addresses.
⚠️ When restoring with new settings (mode 2)Don't forget to update DNS A records, router port forwarding, and DSM Firewall rules for the new domain/IP, and reconfigure the Web Station root folder to point to the new web directory.
