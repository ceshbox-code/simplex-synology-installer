💜 Что это такое

Проект разворачивает на Synology DSM полный серверный стек мессенджера SimpleX Chat: SMP (сообщения, порты 5223/5224), XFTP (файлы, порт 7788) и coturn (звонки, 3478/5349) + веб-панель управления с мониторингом статуса. SimpleX не использует идентификаторы пользователей: у каждого контакта одноразовый адрес, метаданные отсутствуют, шифрование сквозное и пост-квантовое.

Устанавливаются зафиксированные версии образов: SMP/XFTP v6.5.2, coturn 4.6.3-r0.

💜 Что такое SimpleX?

SimpleX — это первый мессенджер, который не требует идентификаторов пользователей: нет номеров телефонов, никнеймов или публичных ключей, привязанных к личности. Вместо этого каждый пользователь получает уникальные одноразовые адреса для каждого соединения.

🌍ДецентрализацияВаш сервер — ваши правила
🔄Квантово-устойчивыйДвойная защита

💡 Почему SimpleX уникален?

  • Нет глобальной идентификации — вы не привязаны к номеру телефона или email. Ваш профиль существует только у ваших контактов.
  • Одноразовые адреса — для каждого нового контакта создаётся уникальный адрес. Прекратили общение — адрес удаляется, связь невозможно восстановить.
  • Защита от спама — поскольку каждый адрес уникален и используется только для одного контакта, спам технически невозможен.
  • Вы контролируете сервер — запустив свой SMP, XFTP и TURN сервер, вы полностью контролируете свою инфраструктуру. Никто не видит, кто с кем общается.
  • Квантово-устойчивое шифрование — SimpleX использует двойное шифрование с пост-квантовым алгоритмом, защищая переписку даже от будущих квантовых компьютеров.
  • Открытый исходный код — весь код доступен на GitHub, что позволяет любому независимо проверить его безопасность.
📌 Важно понимать. SimpleX — это не очередной мессенджер с «режимом инкогнито». Это принципиально иная архитектура, где отсутствие идентификаторов заложено в основу. Вы общаетесь не с «пользователем», а с конкретным адресом, который существует ровно столько, сколько нужно.
✅ Итог. Запустив свой сервер SimpleX, вы получаете полностью приватное средство общения, где никто, включая вас как администратора, не может видеть переписку пользователей (она сквозная зашифрована), а метаданные (кто с кем общается) недоступны сторонним наблюдателям.

🧭 С чего начать (карта процессов)

Вся работа ведётся через один управляющий скрипт simplex.sh — интерактивное меню или CLI-команды. Он сам находит нужные рабочие скрипты: сначала локальные копии в папке установки, иначе скачивает их из репозитория и проверяет синтаксис перед запуском.

curl -fsSL https://raw.githubusercontent.com/ceshbox-code/simplex-synology-installer/main/simplex.sh | bash

Или: curl -fsSL …/simplex.sh -o simplex.sh && sudo bash simplex.sh [команда]

📋 1. Подготовка (до запуска скрипта)

  1. Docker / Container Manager — установите через Package Center и откройте один раз для инициализации.
  2. SSH — Панель управления → Терминал и SNMP → включите SSH.
  3. DNS A-записи у регистратора (значение — ваш внешний IP): smp, files, turn, info.smp. Проверка: dig +short smp.ваш-домен и т.д.
  4. Проброс портов на роутере на внутренний IP NAS: 5223 TCP, 5224 TCP, 7788 TCP, 3478 TCP+UDP, 5349 TCP, 49152–65535 UDP (только для звонков).
  5. Брандмауэр DSM: разрешите эти порты (правило выше «запретить всё»; держите второе окно DSM для отката).
  6. Минимум 5 ГБ свободного места на целевом томе.

🚀 2. Установка

sudo bash simplex.sh            # меню → пункт 1
sudo bash simplex.sh install    # сразу новая установка

Скрипт задаст вопросы: язык, том для данных (/volumeX/docker/simplex), папка веб-файлов (/volumeX/web/simplex), внутренний и внешний IP, домен. Затем автоматически: создаст структуру и self-signed TLS-сертификаты, сгенерирует секреты в .env, напишет docker-compose.yml, инициализирует XFTP (fingerprint), загрузит образы, запустит контейнеры, получит fingerprint SMP, создаст веб-панель (index.html, qrsmp.html, .htaccess/.htpasswd), скрипты simplex-backup.sh, status-update.sh, restore.sh, passnew.sh и добавит cron-задачи (бэкап ежедневно 03:00; статус каждую минуту). В конце — отчёт CONNECTION_DETAILS.txt.

⚠️ CONNECTION_DETAILS.txt содержит все секреты — никому не передавайте. Пароль веб-панели показывается один раз.

🌐 3. После установки

  1. Web Station: создайте веб-сервер (Apache 2.4, без PHP), корневая папка — выбранная веб-директория, URL — info.smp.ваш-домен.
  2. Включите AllowOverride для этого виртуального хоста, иначе защита паролем (.htaccess) не сработает.
  3. Откройте https://info.smp.ваш-домен/qrsmp.html, войдите (логин/пароль из CONNECTION_DETAILS.txt) и убедитесь, что SMP/XFTP/TURN — «● РАБОТАЕТ».
  4. Настройте клиент: адреса SMP/XFTP — в Настройки → Серверы → «Настроить вручную»; TURN/STUN — в Настройки → Звонки → ICE servers.

💾 5. Резервное копирование

Обычный бэкап (автоматический)

Ежедневно в 03:00 cron запускает simplex-backup.sh: архив simplex-backup-ГГГГММДД_ЧЧММСС.tar.gz с .env, docker-compose.yml, CONNECTION_DETAILS.txt, identity, данными и сертификатами SMP/XFTP и веб-папкой. Хранение 14 дней в backups/.

Зашифрованный бэкап (по запросу)

Меню 10 / secure-backup: создаёт обычный бэкап, шифрует AES-256-CBC в /volumeN/docker/simp_bkp/ (вне BASE_DIR — переживает uninstall), проверяет архив и удаляет незашифрованный файл.

⚠️ Пароль зашифрованного архива показывается один раз и нигде не сохраняется. Без него архив не восстановить. Зашифрованные архивы не удаляются автоматически — держите копию вне NAS.

🛟 6. Восстановление

sudo bash simplex.sh restore

Шаги скрипта: список всех архивов (backups/, simp_bkp/, текущая папка; для .enc запросит пароль, метод шифрования определяется автоматически) → проверка целостности и вывод содержимого → проверка алгоритма транспортного ключа SMP (должен быть Ed25519; для «битых» RSA-бэкапов предлагается автопочинка с сохранением Fingerprint) → выбор режима: 1) старые настройки или 2) новые (другой том/IP/домен) → остановка контейнеров, распаковка, нормализация прав, запуск, восстановление веб-панели и (по желанию) новый пароль панели → итоговый отчёт с адресами.

⚠️ Режим 2: после восстановления обновите DNS A-записи, проброс портов, брандмауэр и корневую папку Web Station под новый домен/IP.

🗑 7. Полное удаление

sudo bash simplex.sh uninstall

Скрипт предложит сначала создать зашифрованный бэкап (рекомендуется), затем потребует три подтверждения: «y», точный домен и слово DELETE. Удаляются: контейнеры и сети simplex, cron-задачи (резервная копия crontab сохраняется в /tmp), веб-файлы панели и BASE_DIR. Вручную после удаления: удалить виртуальный хост Web Station, DNS-записи, проброс портов и отозвать сертификаты. Журнал удаления — /tmp/simplex-uninstall-*.log.

⚠️ Правовая информация

  • Скрипты предназначены исключительно для личного и семейного использования на собственном оборудовании.
  • Предоставление сервиса неограниченному кругу лиц может повлечь обязанность регистрации ОРИ (ст. 10.1 ФЗ-149); обработка персональных данных — ФЗ-152.
  • Владелец сервера сам отвечает за безопасность, резервное копирование и соблюдение законодательства. Автор скриптов не несёт ответственности за последствия использования.
  • Не публикуйте адреса SMP/XFTP/TURN и QR-коды в открытом доступе.

⚙️ Настройка после установки

  1. Создайте локальный профиль. Имя и аватар хранятся только на вашем устройстве и никуда не отправляются.
  2. Подключите свой сервер для сообщений и файлов. Откройте Настройки → Серверы → «Настроить вручную». Затем в панели управления qrsmp.html нажмите «Показать» и «▦ QR-код» в карточках SMP и XFTP — отсканируйте QR в приложении либо вставьте адреса вручную (формат: smp://fingerprint:пароль@smp.ваш-домен:5224 и xftp://fingerprint:пароль@files.ваш-домен:7788).
  3. Включите звонки через свой TURN. Настройки → Звонки → ICE servers → вставьте три строки из панели (stun:, turn:, turns:) — в панели для этого есть кнопка «📋 Копировать все адреса». Если звонки не нужны — пропустите шаг.
  4. Сохраните и переподключитесь. После сохранения приложение пересоздаст соединения с новыми серверами. Убедитесь, что в панели qrsmp.html все три сервиса показывают «● РАБОТАЕТ», а в приложении нет ошибок подключения.
  5. Добавьте первый контакт. Нажмите «+» → «Пригласить друга» → покажите QR-код собеседнику или отправьте ему ссылку-приглашение. Для каждого контакта создаётся отдельный одноразовый адрес.
  6. Проверьте работу. Отправьте контакту тестовое сообщение и небольшой файл — они должны доставиться через ваши SMP и XFTP. Для проверки звонка позвоните второму устройству.
⚠️ Адреса SMP/XFTP содержат секрет подключения (fingerprint и пароль). Не публикуйте их и не пересылайте серверные QR-коды в открытом доступе — только членам семьи.
💡 Все устройства семьи могут использовать одни и те же серверные адреса, но профиль, контакты и переписка хранятся отдельно на каждом устройстве. На втором телефоне повторите шаги 2–3.

💜 What is this

The project deploys the full SimpleX Chat server stack on Synology DSM: SMP (messages, ports 5223/5224), XFTP (files, port 7788) and coturn (calls, 3478/5349) plus a web control panel with live status monitoring. SimpleX uses no user identifiers: each contact gets a disposable address, there is no metadata, and encryption is end-to-end and post-quantum.

Pinned image versions are installed: SMP/XFTP v6.5.2, coturn 4.6.3-r0.

💜 What is SimpleX?

SimpleX is the first messenger that does not require user identifiers: no phone numbers, nicknames, or public keys tied to identity. Instead, each user receives unique disposable addresses for each connection.

🔐Full PrivacyNo metadata
🌍DecentralizedYour server, your rules

💡 Why is SimpleX unique?

  • No global identification — you are not tied to a phone number or email. Your profile exists only with your contacts.
  • Disposable addresses — each new contact receives a unique address. Stop communicating — the address is deleted, the connection cannot be restored.
  • Spam protection — since each address is unique and used only for one contact, spam is technically impossible.
  • You control the server — by running your own SMP, XFTP and TURN servers, you have full control over your infrastructure. No one sees who is talking to whom.
  • Quantum-resistant encryption — SimpleX uses double encryption with a post-quantum algorithm, protecting your conversations even from future quantum computers.
  • Open source — all code is available on GitHub, allowing anyone to independently verify its security.
📌 Important to understand. SimpleX is not another messenger with an “incognito mode”. It is a fundamentally different architecture where the absence of identifiers is built into the core. You communicate not with a “user”, but with a specific address that exists exactly as long as needed.
✅ Bottom line. By running your own SimpleX server, you get a completely private means of communication where no one, including you as the administrator, can see users' conversations (they are end-to-end encrypted), and metadata (who is talking to whom) is not available to outside observers.

🧭 Start here (process map)

Everything is managed through one control script, simplex.sh — interactive menu or CLI commands. It resolves worker scripts automatically: local copies in the installation folder first, otherwise downloads them from the repository and validates syntax before running.

📋 1. Preparation (before running)

  1. Install Docker / Container Manager via Package Center; open it once.
  2. Enable SSH (Control Panel → Terminal & SNMP).
  3. Create DNS A records: smp, files, turn, info.smp → your external IP.
  4. Forward ports: 5223 TCP, 5224 TCP, 7788 TCP, 3478 TCP+UDP, 5349 TCP, 49152–65535 UDP (calls only).
  5. Allow the same ports in the DSM Firewall.
  6. ≥ 5 GB free space.

🚀 2. Installation

sudo bash simplex.sh install

The script asks: language, data volume, web folder, internal/external IP, domain. Then automatically: directories, self-signed TLS certificates, .env secrets, docker-compose.yml, XFTP initialization, image pull (pinned versions), container start, SMP fingerprints, web panel (index.html, qrsmp.html, .htaccess/.htpasswd), helper scripts and cron jobs (backup daily 03:00; status every minute). Final report: CONNECTION_DETAILS.txt.

⚠️ CONNECTION_DETAILS.txt contains all secrets. The web password is shown only once.

🌐 3. After installation

  1. Web Station: create a web service (Apache 2.4, no PHP), root = your web folder, URL = info.smp.your-domain.
  2. Enable AllowOverride for that virtual host, otherwise password protection won't work.
  3. Open https://info.smp.your-domain/qrsmp.html, log in and verify all services show ● RUNNING.
  4. Configure the client with SMP/XFTP addresses (Settings → Servers → manual) and TURN/STUN (Settings → Calls → ICE servers).

🔧 4. Day-to-day operations

Status — menu 6 / status; logs — menu 7 / logs; refresh panel status — menu 8 / update; plain backup — menu 5 / backup; encrypted backup — menu 10 / secure-backup; password rotation — menu 4 / passnew [login]; reinstall keeping config — menu 2 / reinstall.

💾 5. Backups

Plain: daily at 03:00 via cron (simplex-backup.sh), 14-day retention in backups/; contains config, secrets, SMP/XFTP identity, data, certificates and the web folder.
Encrypted: menu 10 / secure-backup — AES-256-CBC archive in /volumeN/docker/simp_bkp/ (outside BASE_DIR), verified, plain file deleted afterwards.

⚠️ The encrypted-archive password is shown once and stored nowhere. Encrypted archives are not auto-deleted — keep a copy off the NAS.

🛟 6. Restore

sudo bash simplex.sh restore

Lists all archives (incl. .enc — password required, encryption mode auto-detected), verifies integrity, lists contents, checks the SMP transport key algorithm (Ed25519; offers auto-repair for RSA-overwritten backups, preserving the Fingerprint), then restores with old settings (mode 1) or new volume/IP/domain (mode 2), restarts containers, restores the web panel and optionally rotates the panel password.

⚠️ Mode 2: update DNS records, port forwarding, firewall and the Web Station root folder afterwards.

🗑 7. Uninstall

sudo bash simplex.sh uninstall

Offers an encrypted backup first (recommended), then triple confirmation (y, exact domain, DELETE). Removes containers and simplex networks, cron entries (crontab backed up), panel web files and BASE_DIR. Manual follow-up: remove the Web Station virtual host, DNS records, port forwarding, revoke certificates. Log: /tmp/simplex-uninstall-*.log.

  1. Create a local profile. The name and avatar are stored only on your device and are never sent anywhere.
  2. Connect your server for messages and files. Open Settings → Servers → “Configure manually”. Then in the control panel qrsmp.html press “Show” and “▦ QR code” in the SMP and XFTP cards — scan the QR in the app or paste the addresses manually (format: smp://fingerprint:password@smp.your-domain:5224 and xftp://fingerprint:password@files.your-domain:7788).
  3. Enable calls via your TURN. Settings → Calls → ICE servers → paste the three lines (stun:, turn:, turns:) from the panel — it has a “ Copy all addresses” button for that. Skip this step if you don't need calls.
  4. Save and reconnect. After saving, the app re-establishes connections to the new servers. Make sure all three services show “● RUNNING” in qrsmp.html and the app reports no connection errors.
  5. Add your first contact. Tap “+” → “Invite a friend” → show the QR code to your peer or send an invitation link. Each contact gets a separate disposable address.
  6. Verify operation. Send a test message and a small file — they must be delivered via your SMP and XFTP. Place a test call to a second device.
⚠️ SMP/XFTP addresses contain connection secrets (fingerprint and password). Do not publish them or the server QR codes — share only with family members.
💡 All family devices can use the same server addresses, but the profile, contacts and conversations are stored separately on each device. Repeat steps 2–3 on the second phone.
